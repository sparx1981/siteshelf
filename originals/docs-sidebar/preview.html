Authentication

Every request to the Forge API must be signed with a secret key. This page explains how to create keys, send them and keep them safe.

Create an API key

Open Settings → Developers and press Create key. Give the key a name you will recognise and choose the scopes it needs. Keys are shown once, so copy yours straight away.

TipCreate separate keys for development and production so you can rotate one without touching the other.

Send your key

Pass the key in the Authorization header as a bearer token on every request.

bash
curl https://api.forge.example/v2/projects \
  -H "Authorization: Bearer $FORGE_KEY"
javascript
const res = await fetch('https://api.forge.example/v2/projects', {
  headers: { Authorization: `Bearer ${process.env.FORGE_KEY}` }
});
const projects = await res.json();

Reading the response

A successful call returns JSON. If authentication fails you will get a 401 with a machine-readable error code.

json
{
  "error": {
    "code": "invalid_key",
    "message": "The API key provided is not valid."
  }
}

Status codes

CodeMeaningWhat to do
200SuccessRead the body
401Missing or invalid keyCheck the header
403Key lacks the scopeAdd the scope
429Too many requestsBack off and retry

Keeping keys safe

NoteNever commit keys to source control or ship them in browser code. Use environment variables on the server.

If a key leaks, revoke it from the same Developers page. Revocation takes effect within seconds and cannot be undone.
