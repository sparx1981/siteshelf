Build a single-page "Fluid Type Calculator" tool for an invented design-systems site, "Stepwise": enter a smallest and largest viewport and font size, and get a precise CSS clamp() value, then generate a complete fluid type scale (steps -2 to 6) and see it applied live to a sample article inside a resizable browser frame. Everything runs in the page.

Canvas & base: Warm drafting-paper feel: page #f4efe4 with a faint 24px blueprint grid in rgba(30,60,50,.06), panels #fffdf7 with a 1px #d9d1bd border and 14px radius, ink #1d2b26 (13.9:1), secondary #56655f (5.6:1), accent forest #1f6b4f (white text 6.6:1), highlight amber #e0a526 used only for the live "current viewport" marker. Invented brand "Stepwise" with a small stair-step logomark drawn as an inline SVG.

Typography: "Fraunces" 600 for the title (clamp 30 to 52px) and the sample article headings; "Inter" 400/500/600 for UI at 14 to 15px; "JetBrains Mono" 500 for values and CSS (tabular numerals). Eyebrow 12px, 0.16em tracking, uppercase, forest.

Imagery & art direction: The sample article inside the browser frame is a "field notes" feature with a painted hero illustration (inline SVG generated by the scene library: a dawn mountain-and-lake landscape in soft peach, slate blue and pine, lightly grained with a gentle vignette), a drop-cap-free serif headline, a byline with a small painted portrait avatar, two paragraphs and a pull-quote, so type changes read against a real layout. The browser frame has traffic-light dots, an address pill "stepwise.example/field-notes" and a width ruler along its top edge with tick marks every 100px and an amber marker at the current width. A small SVG chart plots font size (y) against viewport width (x): a flat segment, a sloped segment and a flat segment, with draggable-looking handles at the two breakpoints. Media slots for real photography: one 1600x800 landscape for the article hero (object-fit cover, alt text).

Layout: Header (eyebrow "Stepwise", title "Fluid Type Calculator", one-line intro). Two columns above 1000px. Left: Inputs panel with four number fields (Min viewport 320, Max viewport 1280, Min size 16, Max size 24) with px suffix, a unit toggle for output (rem or px) and a root size field (16); a Result panel with the large monospace clamp value, a Copy button, and a second line showing the slope and intercept; then the Scale panel (Min ratio select 1.125 to 1.5, Max ratio select, base steps) as a table: Step, Min px, Max px, clamp value, with a Copy-all as CSS custom properties button. Right (sticky): the browser frame preview with a Viewport slider below (200 to 1600 px) showing "Viewport 744 px, h1 31.2 px", and the curve chart beneath.

Copy: Default result "clamp(1rem, 0.8333rem + 0.8333vw, 1.5rem)" style, computed live. Messages: "Copied clamp(...)", "Scale copied as 9 custom properties." and the validation "Max viewport must be larger than min viewport."

Interaction: slope = (maxSize - minSize) / (maxVw - minVw); intercept = minSize - slope x minVw; preferred = intercept/root rem + (slope x 100) vw; output clamp(min, preferred, max) with values rounded to 4 decimals and trailing zeros trimmed; swap min and max automatically for shrinking sizes (min/max inside clamp ordered). Scale: size at step n = base x ratio^n for min and max sides; each step gets its own clamp. The preview applies the h1, h2, body and caption steps to the sample article by setting CSS custom properties from the computed clamp expressions, so the real browser clamp is used, and the frame width is set from the slider (the article inside is a container with its own width, using container-based vw replaced by a computed value: because vw refers to the window, the preview instead computes sizes in JavaScript for the simulated width and applies them in px). The ruler marker and chart marker move with the slider; keyboard arrows adjust the slider by 10px (Shift 100px). Inputs validate on input with inline messages and aria-invalid. Copy buttons use the Clipboard API inside try/catch with a polite live-region announcement. Last inputs persist in localStorage inside try/catch.

Technique notes: The chart is an SVG path with three segments computed from the same slope/intercept; the amber marker position uses the same function as the preview so the two never disagree. Easing is not needed; only the frame width change animates (150ms) unless reduced motion.

Responsive: Under 1000px the preview moves above the inputs (not sticky), the scale table scrolls inside its own container and the clamp output wraps; no horizontal scroll at 390px; the frame is scaled to fit by clamping its simulated width to the container and showing the actual simulated width as text.

Rules: Single HTML file, Google Fonts link, inline CSS and JS, no libraries or external images. [hidden]{display:none!important}. Visible focus 3px #1d2b26 outline with 2px offset. Every number shown as text as well as in visuals. Respect prefers-reduced-motion. Invented names only.
