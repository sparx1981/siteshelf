Build a single-page "Colour Blindness Simulator" tool for an invented accessibility site, "Huewise": edit a six-colour palette and see how a painted scene, a chart and a status row look under the main colour vision deficiencies, with a severity slider and plain-language warnings for colour pairs that become hard to tell apart. Everything runs in the page.

Canvas & base: A calm studio-neutral look. Page #f6f4ef, panels #ffffff with a 1px #e0dbcf border and 16px radius, ink #1b1b1f (16.9:1), secondary #55525a (7.4:1), accent indigo #4a35d6 (white text 7.1:1), warning amber text #7a4a00 on #fdecc8, ok green text #1d6a3a on #dff3e5. Neutral grey chrome so that only the palette brings colour. Invented brand "Huewise" with a three-ring overlapping logomark in the first three palette colours.

Typography: "Outfit" 600 for the title (clamp 30 to 52px) and card headings; "Inter" 400/500/600 for UI at 14 to 15px; "IBM Plex Mono" 500 for hex values (tabular numerals). Eyebrow 12px, 0.16em tracking, uppercase, indigo.

Imagery & art direction: The hero and every simulation card show the same painted garden still life drawn in inline SVG using only the six palette colours for the meaningful parts: six flowers on stems (each petal ring in one palette colour, with a darker centre, a soft shadow and a few painted leaf strokes), a wooden trellis, a red-and-green style status lantern row, and a small donut chart with legend, all over a soft sky-to-lawn background in neutral blue and sage that never changes. The scene is deliberately busy with colour-coded information so confusion is visible: a traffic light with three discs, three status badges (OK, Warning, Error) and chart slices labelled with letters. Media slots for real photography: optionally one 1200x800 photograph of flowers in the hero card (the CSS filters apply to it too).

Layout: Header (eyebrow "Huewise", title "Colour Blindness Simulator", a one-line intro). Palette panel: six swatch rows each with a colour input, a hex text field and a letter badge A to F (matching the chart legend) and an automatic colour name worked out from hue and lightness, such as red, dark blue or light green, a Presets select (Traffic lights, Chart default, Brand set, Colour-blind safe), Randomise and Reset buttons. Severity panel: a range slider 20 to 100 percent ("Severity 100%") that affects protanomaly, deuteranomaly and tritanomaly (the "-opia" names appear at 100%). Simulation grid: five cards (Normal, Protanopia, Deuteranopia, Tritanopia, Monochrome), each with the scene, the six simulated swatches with hex values and a status line "Looks fine" or "2 pairs hard to tell apart". Below: a Findings list that names the confusable pairs per type ("A (red) and B (green) look alike under Deuteranopia (difference 6, needs 15)") and a "How to fix" tip (add a pattern, label directly or change lightness).

Copy: Tips: "Add labels or patterns so colour is never the only signal." "Change lightness, not just hue: pairs that differ in brightness stay distinct." Statuses: "Looks fine", "1 pair hard to tell apart", "4 pairs hard to tell apart". Messages: "Palette reset." "Loaded Colour-blind safe."

Interaction: Simulation uses the linear-RGB matrices for protan, deutan and tritan dichromacy (Machado-style, severity 1.0) blended with identity by severity (M = (1 - s) I + s M), and luminance weights 0.2126, 0.7152, 0.0722 for monochrome. The painted scenes are shown through SVG feColorMatrix filters (color-interpolation-filters linearRGB) referenced by CSS filter:url(#id) so the whole image, including any uploaded photo, is transformed; swatch hex values are computed in JavaScript with the same maths (sRGB to linear, matrix, clamp, back to sRGB). Pair analysis: convert normal and simulated colours to CIELAB and take delta E 76; a pair is flagged when the normal difference is at least 30 and the simulated difference is below 15; list each flagged pair once per type with both values. Editing a colour input or hex field (3 or 6 digits, validated, with an inline error) updates everything immediately (debounced 60ms), and the severity slider updates filter matrices without rebuilding the DOM. Presets and Randomise replace the palette; Reset restores defaults. Cards are labelled regions with the status text; the findings list uses aria-live polite after the user pauses (600ms). Palette persists in localStorage inside try/catch.

Technique notes: Filter matrix for a 3x3 matrix m with severity s: values="a b c 0 0 d e f 0 0 g h i 0 0 0 0 0 1 0" with each coefficient = (1 - s) x identity + s x m. Update the filter by setting the feColorMatrix values attribute; the CSS filter reference does not change. Keep every SVG id unique per page and give the scene its own gradients prefixed per card.

Responsive: Under 1000px the palette and severity panels stack above the grid; cards become 2 per row then 1 per row under 560px; hex fields stay 44px high; no horizontal scroll at 390px.

Rules: Single HTML file, Google Fonts link, inline CSS and JS, no libraries or external images. [hidden]{display:none!important}. Visible focus 3px #1b1b1f outline with white offset. Colour is never the only signal in the UI itself: every swatch shows its hex and name, every status is written. State plainly that this is an approximation, not a medical test. Respect prefers-reduced-motion. Invented names only.
