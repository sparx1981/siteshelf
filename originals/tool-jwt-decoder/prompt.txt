Build a single-page "Token Decoder" tool for an invented developer-tools site, "Sealwright": paste a sample JSON web token and see its three parts split, colour-coded and decoded, with human-readable claims and a live expiry countdown. It decodes only; it never verifies and never sends anything anywhere. Everything runs in the page.

Canvas & base: A calm "vault" look. Page #0e1322 with a soft top glow, panels #161d33 with a 1px #2a3556 border and 14px radius, ink #eef1fb (15.2:1), secondary #a9b4d3 (8.4:1). Three part colours used consistently everywhere: header coral #ff8f6b, payload violet #b9a2ff, signature teal #52d6c4 (all above 7:1 on the panel). Status colours: valid #5fd38d, expired #ff6b7a, not-yet-valid #f2c14e. Invented brand "Sealwright" with a tiny wax-seal logomark.

Typography: "Space Grotesk" 600 for the title (clamp 30 to 52px) and panel headings; "Inter" 400/500/600 for UI; "JetBrains Mono" 500 at 13 to 14px for token, JSON and values (tabular numerals). Eyebrow 12px, 0.16em tracking, uppercase.

Imagery & art direction: A painted hero banner (inline SVG built from the scene library's abstract generator in deep indigo, violet, teal and coral, lightly grained and vignetted) sits behind the title like an engraved banknote guilloche, with a large illustrated wax seal on the right: a scalloped disc with a pressed monogram "S", soft highlights, a ribbon in the three part colours, and a cast shadow on paper. The seal changes with the token: green with a check glyph when valid, red with a cross when expired, amber with a clock glyph when not yet valid, grey with a dash when malformed or unsigned. Each decoded panel has a small engraved icon (a keyhole, a letter, a stamp). Media slots for real photography: none required; optionally a 1600x400 macro photograph of a wax seal for the banner.

Layout: Banner with eyebrow, title "Token Decoder", a one-line notice "Decoding is not verifying. Never paste real secrets." and the seal. Below, two columns above 960px. Left: Token panel with a labelled textarea (rows 6, monospace, spellcheck off), preset buttons ("Valid for 2 hours", "Expired", "Not valid yet", "No signature", "Malformed"), Paste sample and Clear buttons, and an Anatomy strip showing three coloured blocks "HEADER", "PAYLOAD", "SIGNATURE" with the first 18 characters and their byte lengths. Below that the Claims table. Right: Header JSON and Payload JSON panels (pretty-printed with syntax colouring: keys, strings, numbers, booleans), a Signature panel (base64url text, byte length, algorithm from the header with a one-line plain explanation such as "HS256: shared-secret HMAC; the signature cannot be checked here") and a Status card (seal, status word, countdown).

Copy: Notice: "Decoding is not verifying: anyone can read a token's contents, and this tool cannot tell whether it is genuine." Messages: "Token is valid for another 1h 59m", "Token expired 3 days ago", "Token becomes valid in 10 minutes", "This does not look like a token: expected 3 parts separated by dots, found 2.", "Header is not valid JSON."

Interaction: Parse on every input: split on ".", require 2 or 3 parts, base64url-decode (replace - and _, pad with =, atob, UTF-8 decode safely), JSON.parse header and payload with specific errors per part, highlighting the failing block in the Anatomy strip. Presets build their tokens in the page (header {alg:"HS256",typ:"JWT"} and a payload with iss "https://auth.example.com", sub "user_4821", aud "demo-app", name "Alex Sample", scope, iat, nbf and exp relative to now) using base64url encoding and a fixed fake signature; no real keys exist. Claims table: known claims (iss, sub, aud, exp, nbf, iat, jti, scope) get friendly labels and explanations; time claims show an ISO date plus relative text ("in 1h 59m", "3 days ago"). Status is computed from exp and nbf against the current time; the countdown updates every second but the polite live region only announces when the status changes or at 5-minute marks. Copy buttons on each panel (Clipboard API in try/catch, polite message). Tab keys reach all controls; the textarea has a label and describes its own error with aria-describedby; errors use role=alert.

Technique notes: The seal is drawn with an SVG path whose scallops come from r = R + a x sin(n x theta) sampled every 4 degrees; its colour transitions with a 300ms fill transition, disabled under reduced motion. JSON highlighting is a small tokenizer using one regular expression over the pretty-printed string, escaping HTML before wrapping spans.

Responsive: Under 960px the columns stack, the seal drops below the title at 96px, JSON panels scroll inside their own boxes with overflow-wrap:anywhere for long values; no horizontal scroll at 390px.

Rules: Single HTML file, Google Fonts link, inline CSS and JS, no libraries or external images, no network requests of any kind. [hidden]{display:none!important}. Visible focus 3px #ffffff outline with a dark 2px offset. Never rely on colour alone: part names and status words are always text. Respect prefers-reduced-motion. Invented names and example.com addresses only.
